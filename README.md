# 🚀 OmniCommerce AI (OCA)
> **All-in-One Social Commerce & Omnichannel Platform**
> ລະບົບສູນກາງການຄ້າຜ່ານໂຊຊ້ຽວມີເດຍ, ແຕ່ງຮູບ AI, ດັກ CF Live, ສະຕ໋ອກສູນກາງ ແລະ ບັນຊີອັດສະລິຍະ ມາດຕະຖານສາກົນລະດັບ Enterprise (12 ໂມດູນ).

## 📌 ໂຄງສ້າງ 12 ໂມດູນຫຼັກຂອງ OmniCommerce AI

### ⚡ ສ່ວນດ່ານໜ້າ ແລະ ການຂາຍ (Sales & Frontline)
1. **Omnichannel Inbox:** ຮວມແຊັດສູນກາງ Facebook Messenger, Instagram DM, TikTok Messages, LINE OA ພ້ອມ AI Smart Reply ແລະ ເປີດບິນປິດການຂາຍໃນແຊັດ.
2. **Social Multi-Posting & Scheduler:** ຂຽນຄັ້ງດຽວ ໂພສ ແລະ ຕັ້ງເວລາລ່ວງໜ້າກະຈາຍລົງທຸກແພລັດຟອມ ພ້ອມ AI Copywriter ຊ່ວຍຂຽນແຄັບຊັນ & ແຮຊແທັກ.
3. **AI Image Studio:** Web Canvas Editor ແຕ່ງຮູບສິນຄ້າ, ຕັດພື້ນຫຼັງ 1-Click, ສ້າງສາກຫຼັງສະຕູດິໂອດ້ວຍ AI, ໃສ່ໂລໂກ້/ລາຄາ, ປັບຂະໜາດຮູບໃຫ້ຖືກຕາມແຕ່ລະໂຊຊ້ຽວ.
4. **Live & Post CF Engine:** ດັກຄອມເມັ້ນເວລາ Live ສົດ ແລະ ໂພສຂາຍ, ດັກຈັບລະຫັດ CF, ດຶງເຂົ້າ Inbox ອັດຕະໂນມັດ ພ້ອມອອກໃບບິນ QR Code ທີ່ມີເວລານັບຖອຍຫຼັງຕັດສະຕ໋ອກ.
5. **Promotion & Marketing Engine:** Flash Sale ໂມງນັບຖອຍຫຼັງ, Bundle ຊື້ຄູ່ຖືກກວ່າ, 1 ແຖມ 1 (BOGO), Abandoned Cart Auto-Recovery ດັກສົ່ງແຊັດຫາລູກຄ້າທີ່ປະຖິ້ມກະຕ່າ.
6. **Affiliate & Dropship Portal:** ລະບົບນາຍໜ້າ KOL/Influencer ແບ່ງ % ຄ່ານາຍໜ້າອັດຕະໂນມັດ ແລະ ລະບົບຕົວແທນຂາຍ Dropship (ເຫັນລາຄາສົ່ງ, ດາວໂຫຼດສື່).

### ⚙️ ສ່ວນສາງ ແລະ ການປະຕິບັດການ (Core & Operations)
7. **E-Commerce Storefront & Central Inventory:** ໜ້າເວັບໄຊຂາຍສິນຄ້າໂຫຼດໄວ ຮອງຮັບມືຖື 100% + ສະຕ໋ອກສູນກາງ Real-time (ຕັດສະຕ໋ອກພ້ອມກັນທັງເວັບ, ແຊັດ, ແລະ Live ປ້ອງກັນການຂາຍເກີນ).
8. **Smart Logistics Hub & Multi-Warehouse:** ຮອງຮັບຫຼາຍສາງ/ຫຼາຍສາຂາ, ລະບົບຍິງບາໂຄດກວດກ່ອນແພັກ (Scan-to-Verify), ເຊື່ອມຕໍ່ API ຂົນສົ່ງ, ພິມໃບປະໜ້າ Thermal 100x150mm ແລະ ສົ່ງເລກ Tracking ຫາແຊັດລູກຄ້າ.
9. **Automation Workflows & AI Slip Verification:** AI ອ່ານສະລິບໂອນເງິນ (OCR) ອັດຕະໂນມັດ ປັບສະຖານະບິນທັນທີ ແລະ ຕັ້ງກົດ IFTTT ແຈ້ງເຕືອນສະຕ໋ອກໃກ້ໝົດເຂົ້າ Telegram/LINE.

### 📊 ສ່ວນການວິເຄາະ ແລະ ບໍລິຫານ (Control & Intelligence)
10. **Analytics & Financial Reports:** ລາຍງານກຳໄລ-ຂາດທຶນສຸທິ (P&L), ຕົ້ນທຶນ COGS, ສິນຄ້າຂາຍດີ, ສິນຄ້າຄ້າງສະຕ໋ອກ (Deadstock), ປຽບທຽບຍອດຂາຍແຕ່ລະຊ່ອງທາງ.
11. **CRM & Customer Loyalty:** ຮວມປະຫວັດລູກຄ້າ 360°, ລະບົບສະມາຊິກ VIP (Bronze, Silver, Gold, Platinum), ສະສົມແຕ້ມແລກສ່ວນຫຼຸດ, ຈັດກຸ່ມລູກຄ້າ RFM.
12. **Multi-Role Team & Staff Management:** ແຍກສິດພະນັກງານ (RBAC), ວັດ KPI ຄວາມໄວໃນການຕອບແຊັດ ແລະ ຍອດປິດການຂາຍ, ບັນທຶກ Audit Trail ປ້ອງກັນການທຸຈະລິດ.

## 🛠️ Recommended Tech Stack

* **Frontend:** Next.js (App Router), TailwindCSS, Shadcn/ui, Fabric.js (Canvas Image Editor).
* **Monorepo:** pnpm workspaces + Turborepo.
* **Backend:** NestJS + TypeScript, WebSockets (Socket.io), BullMQ workers.
* **Database & Caching:** PostgreSQL + Prisma ORM, Redis + BullMQ (ຈັດຄິວ Webhook & Posting).
* **AI & Storage:** Gemini API (Multimodal Chat, Caption, OCR), Cloudflare R2 / AWS S3.

## ▶️ Getting Started

```bash
cp .env.example .env
pnpm install
pnpm infra:up      # ເປີດ PostgreSQL + Redis
pnpm dev
```

**ທາງເລືອກທີ່ບໍ່ໃຊ້ Docker** (Postgres + Redis ແບບເບົາ ຜ່ານ npm):

```bash
cp .env.example .env
pnpm install
pnpm infra:local   # ເປີດໃນ terminal ແຍກ ແລ້ວປະໄວ້ (Ctrl+C ເພື່ອຢຸດ)
pnpm db:deploy
pnpm db:seed
pnpm dev
```

- ພອດໃນ `.env` (`POSTGRES_PORT`, `REDIS_PORT`, `DATABASE_URL`, `REDIS_URL`) ຕ້ອງກົງກັນ; `pnpm infra:local` ຈະພິມ URL ທີ່ຖືກຕ້ອງ. ຖ້າພອດຖືກໃຊ້ຢູ່ ມັນຈະຢຸດພ້ອມຂໍ້ຄວາມບອກ.
- ການຣັນຄັ້ງທຳອິດ ດາວໂຫຼດ Postgres (~100MB) ແລະ compile Redis ຈາກ source (ຕ້ອງມີ Xcode Command Line Tools ຫຼື `make` + C compiler; ໃຊ້ເວລາ 1-2 ນາທີ). ຂໍ້ມູນ Postgres ເກັບໃນ `.local/postgres` (ຖືກ ignore ໂດຍ git).
- `pnpm infra:local` ໃຊ້ Postgres 18 (embedded) ສ່ວນ `docker-compose.yml` ໃຊ້ Postgres 16. Migration ທັງ 5 ໄຟລ໌ໄດ້ກວດແລ້ວວ່າ apply ໄດ້ສະອາດບໍ່ມີ drift ເທິງ 16 ແລະ 18 (ກວດ 16 ດ້ວຍ `embedded-postgres@16` ເມື່ອ 2026-10-05); migration ໃໝ່ຄວນກວດທັງສອງເວີຊັນ.

> ໝາຍເຫດ: `packages/database` (Prisma schema + Auth/RBAC + seed), `packages/config`, `packages/shared`, `apps/api` (login, RBAC, staff/roles, `/health`; module ອື່ນເປັນໂຄງເປົ່າ) ແລະ `apps/worker` (BullMQ, queue `system`/`ping`) ພ້ອມໃຊ້. `apps/admin` (login, shell, ພະນັກງານ, ບົດບາດ ແລະ ສິດ) ແລະ `apps/storefront` (placeholder) ພ້ອມໃຊ້; UI ທັງໝົດຢູ່ `packages/ui` ຕາມ `docs/DESIGN.md`. ເປີດໃຊ້: `pnpm dev` (admin :3000, api :3001, storefront :3002); ໃນ `.env` ຕ້ອງຕັ້ງ `REFRESH_COOKIE_PATH=/api/auth` (ເບິ່ງ `.env.example`). Test ຂອງ api ແລະ worker ໃຊ້ Postgres + Redis ຈິງ (`pnpm infra:up`). ໂມດູນ Inventory (Phase 1): API ສິນຄ້າ/ສາງ/ສະຕ໋ອກ/ຄຳສັ່ງຊື້ ແລະ job ຄືນສະຕ໋ອກທີ່ໝົດເວລາຈອງ ພ້ອມໃຊ້ (`POST /orders` ຮອງຮັບ header `Idempotency-Key` ເພື່ອກັນສ້າງບິນຊ້ຳ ເມື່ອ client ສົ່ງຄືນ); ໜ້າ admin ພ້ອມໃຊ້: ສິນຄ້າ/variants, ສາງ, ໝວດໝູ່, ຕັ້ງຄ່າຮ້ານ, `/stock` (ຍອດ + ປະຫວັດ + ຮັບ/ປັບ/ໂອນ/ຮັບຄືນ/ຕັ້ງເກນ) ແລະ `/orders` (ລາຍການ, ສ້າງບິນດ້ວຍມື, ລາຍລະອຽດ + ນັບຖອຍການຈອງ + ປຸ່ມຕາມສະຖານະ/ສິດ); ຫຼັງ login ລະບົບພາໄປໜ້າທຳອິດທີ່ບົດບາດນັ້ນເຂົ້າໄດ້. ໝາຍເຫດ: ຖ້າ DB dev ເກົ່າ ຕ້ອງ `pnpm --filter @oca/database db:deploy` ເພື່ອໃຫ້ migration `order_idempotency_key` ຖືກໃຊ້ກ່ອນສ້າງບິນ.

> **Inbox (Phase 1, sub-project 2a):** ພ້ອມໃຊ້ສຳລັບ Facebook Messenger: ໜ້າ `/inbox` (ລາຍການ, ແຊັດ, ແຖບຂ້າງ ລູກຄ້າ/ຜູ້ຮັບຜິດຊອບ/ບິນ), ຕອບລູກຄ້າ, realtime ຜ່ານ SSE + Redis, ແລະ ເປີດບິນຈາກແຊັດ (`/orders/new?conversationId=`). ຍັງບໍ່ພິສູດກັບ Meta ຈິງ: ພັດທະນາດ້ວຍ simulator, ຕົວຢ່າງ `SIM_API_URL=http://127.0.0.1:3001 FACEBOOK_APP_SECRET=<secret> pnpm --filter @oca/channels simulate say U1001 "ສະບາຍດີ"` (ແລະ `simulate comment POST_1 U1001 "ນາງ ກ" "CF A1 2"` ຈຳລອງຄອມເມັ້ນ CF; `simulate graph 4010` ເປັນ Graph ປອມ ແລະພິມ private/public reply; ຕັ້ງ `FACEBOOK_GRAPH_BASE_URL=http://127.0.0.1:4010` ໃນ dev ເທົ່ານັ້ນ). ການຕັ້ງ Meta App, env ແລະ ຂໍ້ຈຳກັດ: `docs/DEPLOYMENT-NOTES.md` ຂໍ້ 11. ຕ້ອງ `pnpm --filter @oca/database db:deploy` ເພື່ອໃຫ້ migration `inbox` ຖືກໃຊ້.

> **Live & Post CF (Phase 1, sub-project 4a):** ໜ້າ `/live` (ສິດ `live-cf:read`/`live-cf:write`): ສ້າງ session (Live/ໂພສ + id ໂພສ Facebook), ຜູກລະຫັດ CF → ສິນຄ້າ (ຈຳກັດຈຳນວນໄດ້), ເລີ່ມ/ຈົບ, ແລະ ledger ຄອມເມັ້ນ (ຜົນ, ລິ້ງບິນ, ສະຖານະຂໍ້ຄວາມ + ສົ່ງໃໝ່) ທີ່ອັບເດດທຸກ 5 ວິ ຂະນະ LIVE. ຂໍ້ມູນໂອນທີ່ແນບທ້າຍສະຫຼຸບບິນ CF ຕັ້ງໃນ `/settings`. ລອງດ້ວຍ simulator: `simulate comment <id ໂພສ> U1001 "ນາງ ກ" "CF A1 2"` (API ຕ້ອງມີ `FACEBOOK_APP_SECRET` ແລະ `FACEBOOK_WEBHOOK_VERIFY_TOKEN`). ຕ້ອງ `pnpm --filter @oca/database db:deploy` ເພື່ອໃຫ້ migration `cf_engine` ຖືກໃຊ້.

> **Host screen (4b):** ໜ້າເຕັມຈໍ `/live/:id/host` (ປຸ່ມ "ເປີດ Host screen" ໃນ `/live/:id`) ສຳລັບແທັບເລັດ/ຈໍທີສອງຂ້າງຄົນ Live: ສິນຄ້າທີ່ກຳລັງນຳສະເໜີ (ເລືອກດ້ວຍປຸ່ມດາວໃນຕາຕະລາງລະຫັດ ຫຼື ແຕະ card ເທິງຈໍ), ຈຳນວນທີ່ຍັງຂາຍໄດ້ຕໍ່ລະຫັດ, ຍອດລວມ ແລະ CF ລ່າສຸດ. ອັບເດດທັນທີຜ່ານ SSE `GET /live-sessions/:id/events` (Redis channel `oca:live:events`; worker ກໍ publish ເມື່ອບິນ CF ໝົດເວລາ). ຕ້ອງ `db:deploy` ເພື່ອໃຫ້ migration `live_featured_item` ຖືກໃຊ້.

> **Logistics Hub (Phase 2, sub-project 8a):** `/fulfillment` ລາຍການບິນທີ່ຈ່າຍແລ້ວລໍແພັກ (ຍິງເລກບິນເພື່ອເປີດ, ເລືອກຫຼາຍບິນພິມໃບປະໜ້າ) → ໜ້າແພັກ: ຍິງບາໂຄດ/SKU ດ້ວຍເຄື່ອງຍິງ ຫຼື ກ້ອງ ຈົນຄົບ (ຜູ້ມີ `orders:write` ຂ້າມໄດ້ດ້ວຍເຫດຜົນ), ແກ້ຂໍ້ມູນຜູ້ຮັບ, ພິມໃບປະໜ້າ 100×150 mm (Code128), ສົ່ງອອກພ້ອມບໍລິສັດ + ເລກ tracking (ຕັດສະຕ໋ອກ) ແລ້ວແຈ້ງລູກຄ້າທາງແຊັດອັດຕະໂນມັດ. ບໍລິສັດຂົນສົ່ງຕັ້ງທີ່ `/couriers`. ສິດ `logistics:read/write`. ຕ້ອງ `db:deploy` ເພື່ອໃຫ້ migration `logistics` ຖືກໃຊ້; ລາຍລະອຽດ `docs/DEPLOYMENT-NOTES.md` ຂໍ້ 13.

> **Social Posting (Phase 3, sub-project 2a):** `/posts` ລາຍການ + ປະຕິທິນເດືອນ (ເວລາລາວ) → ຟອມໂພສ: ຂໍ້ຄວາມ, ຮູບ ≤ 10 (ອັບໂຫຼດ JPEG/PNG/WebP ≤ 8 MB ເກັບເທິງ disk ທີ່ `MEDIA_DIR`, ເລືອກຈາກຮູບສິນຄ້າ ຫຼື URL https), ຕົວຢ່າງແບບ Facebook, ໂພສທັນທີ ຫຼື ຕັ້ງເວລາ, ຍົກເລີກ/ລອງໃໝ່. ຕົວໂພສແລ່ນໃນ API ທຸກ `POSTING_TICK_MS`; ຜູກ session Post CF ແລ້ວລະບົບໃສ່ post id ແລະ ເລີ່ມດັກ CF ໃຫ້ເອງຫຼັງໂພສ. ສິດ `posting:read/write`; ລາຍລະອຽດ `docs/DEPLOYMENT-NOTES.md` ຂໍ້ 14.
