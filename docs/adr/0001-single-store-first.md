# ADR 0001: ພັດທະນາເປັນຮ້ານດຽວກ່ອນ (Single-Store First)

* **ສະຖານະ:** ຕົກລົງແລ້ວ
* **ວັນທີ:** 2026-10-04

## ບໍລິບົດ
OCA ສາມາດສ້າງເປັນລະບົບຂອງຮ້ານດຽວ ຫຼື ເປັນ SaaS ຫຼາຍຮ້ານ (multi-tenant). ທາງເລືອກນີ້ກຳນົດຮູບແບບຖານຂໍ້ມູນ, ການ login ແລະ ການເຊື່ອມຕໍ່ບັນຊີໂຊຊ້ຽວ.

## ການຕັດສິນໃຈ
ໄລຍະທຳອິດພັດທະນາເປັນ **ຮ້ານດຽວ (single-tenant)**.

* ຕາຕະລາງບໍ່ມີ `tenantId`; ການຕັ້ງຄ່າຮ້ານເກັບໄວ້ບ່ອນດຽວ.
* ບັນຊີໂຊຊ້ຽວ (Facebook, Instagram, TikTok, LINE) ເຊື່ອມກັບຮ້ານດຽວ.
* "ຫຼາຍສາງ / ຫຼາຍສາຂາ" ໃນໂມດູນ 8 ຍັງຄົງຮອງຮັບ ເພາະເປັນສາງຂອງຮ້ານດຽວກັນ.

## ຜົນທີ່ຕາມມາ
* ຖານຂໍ້ມູນ ແລະ ສິດການເຂົ້າເຖິງງ່າຍຂຶ້ນ, ພັດທະນາ MVP ໄດ້ໄວ.
* ຖ້າຈະປ່ຽນເປັນ SaaS ໃນອະນາຄົດ ຕ້ອງເພີ່ມ `tenantId` ໃສ່ທຸກຕາຕະລາງ ແລະ ຍ້າຍຂໍ້ມູນ. ເພື່ອຫຼຸດຄ່າໃຊ້ຈ່າຍນັ້ນ ການເຂົ້າເຖິງຖານຂໍ້ມູນທັງໝົດຕ້ອງຜ່ານ `packages/database` ເທົ່ານັ້ນ.
